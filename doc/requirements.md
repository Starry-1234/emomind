# 需求规格说明书

## 1. 引言

### 1.1 编写目的

本文档用于描述 EmoMind 心理测评平台的功能需求、非功能需求及系统约束，为后续概要设计、详细设计和开发实施提供依据。

### 1.2 项目背景

EmoMind 是一个面向个人用户和管理员的心理测评平台。平台提供用户注册登录、心理测评记录管理、文件分析报告生成、AI 心理问答咨询等功能。管理员可通过仪表盘查看平台统计数据。

### 1.3 术语定义

| 术语 | 说明 |
|------|------|
| JWT | JSON Web Token，用于用户认证的令牌机制 |
| SSE | Server-Sent Events，服务器向客户端推送实时数据的技术 |
| Dify | 第三方 AI 平台，提供大模型对话能力 |
| Streak | 用户连续活跃天数 |
| 分析报告 | 对用户上传文件进行心理分析后生成的报告 |
| 测评记录 | 用户完成心理测评后保存的题目、答案和得分记录 |

### 1.4 参考资料

- Spring Boot 官方文档
- Spring Security 参考手册
- OpenAPI 3.0 规范
- Dify API 文档

## 2. 总体描述

### 2.1 系统边界

EmoMind 系统包含以下组成部分：
- Web 前端应用（React）
- REST API 后端服务（Spring Boot）
- PostgreSQL 数据库
- Dify AI 平台（外部集成）

### 2.2 用户角色

| 角色 | 说明 | 权限 |
|------|------|------|
| 普通用户 | 注册并登录的个人用户 | 管理自己的资料、分析报告、测评记录；使用 AI 咨询 |
| 超级用户（管理员） | 平台管理员 | 普通用户所有权限 + 查看统计数据、管理所有用户和测评记录 |

### 2.3 运行环境

**服务端：**
- Java 21 (LTS)
- Spring Boot 3.2
- PostgreSQL 17
- Docker & Docker Compose

**客户端：**
- 现代浏览器（Chrome, Firefox, Safari, Edge）
- 支持 JavaScript 和 WebSocket/SSE

### 2.4 约束条件

- API 接口需兼容现有前端自动生成的 OpenAPI 客户端
- 数据库存储使用无时区 TIMESTAMP，应用层统一使用 CST (Asia/Shanghai)
- 密码哈希使用 BCrypt 算法
- JWT 签名使用 HS256 算法
- Dify API 密钥由服务端管理，不暴露给前端

## 3. 功能需求

### 3.1 认证模块

#### 3.1.1 用户注册

- **需求编号**: AUTH-001
- **需求描述**: 用户通过邮箱和密码注册账号
- **输入**: 邮箱（唯一）、密码、全名（可选）
- **处理**: 验证邮箱格式唯一性，密码加密存储，创建用户记录
- **输出**: 新用户信息
- **异常**: 邮箱已存在、邮箱格式无效、密码过短

#### 3.1.2 用户登录

- **需求编号**: AUTH-002
- **需求描述**: 用户通过邮箱和密码登录，获取 JWT 访问令牌
- **输入**: 邮箱、密码（OAuth2 Password Flow）
- **处理**: 验证邮箱和密码，生成 JWT Token
- **输出**: access_token, token_type
- **异常**: 邮箱不存在、密码错误、账号未激活

#### 3.1.3 Token 验证

- **需求编号**: AUTH-003
- **需求描述**: 验证 JWT Token 的有效性并返回用户信息
- **输入**: Authorization: Bearer {token}
- **处理**: 解析并验证 JWT，查询用户信息
- **输出**: 用户基本信息
- **异常**: Token 过期、Token 无效、用户不存在

#### 3.1.4 密码重置

- **需求编号**: AUTH-004
- **需求描述**: 用户请求密码重置，系统发送重置邮件
- **输入**: 用户邮箱
- **处理**: 生成重置 Token（48 小时有效），发送含重置链接的邮件
- **输出**: 邮件发送成功提示（无论邮箱是否存在，返回相同响应）
- **异常**: 邮件服务不可用

#### 3.1.5 密码修改

- **需求编号**: AUTH-005
- **需求描述**: 用户通过重置 Token 或当前密码修改密码
- **输入**: 当前密码 + 新密码 或 重置 Token + 新密码
- **处理**: 验证当前密码或重置 Token，更新密码哈希
- **输出**: 修改成功提示
- **异常**: 当前密码错误、Token 无效或过期、新密码不符合要求

#### 3.1.6 连续活跃天数更新

- **需求编号**: AUTH-006
- **需求描述**: 每次认证请求自动更新用户的连续活跃天数
- **处理规则**:
  - 首次活跃：streak_days = 1
  - 连续活跃（昨天有记录）：streak_days += 1
  - 中断后重新活跃：streak_days = 1
  - 同一天多次请求：不更新
- **时区**: Asia/Shanghai

### 3.2 用户管理模块

#### 3.2.1 获取当前用户信息

- **需求编号**: USER-001
- **需求描述**: 获取当前登录用户的详细信息
- **输出**: 用户 ID、邮箱、全名、是否激活、是否超级用户、streak_days、last_active_date

#### 3.2.2 更新当前用户信息

- **需求编号**: USER-002
- **需求描述**: 更新当前用户的邮箱或全名
- **输入**: 邮箱（可选）、全名（可选）
- **约束**: 邮箱修改时不能与其他用户重复

#### 3.2.3 删除当前用户

- **需求编号**: USER-003
- **需求描述**: 用户删除自己的账户
- **约束**: 删除用户时级联删除其所有关联数据（分析报告、测评记录）

#### 3.2.4 获取所有用户列表

- **需求编号**: USER-004
- **需求描述**: 管理员获取平台所有用户列表（分页）
- **输入**: skip, limit
- **权限**: 仅超级用户
- **输出**: 用户列表 + 总数

#### 3.2.5 创建用户

- **需求编号**: USER-005
- **需求描述**: 管理员创建新用户
- **输入**: 邮箱、密码、全名、是否超级用户
- **权限**: 仅超级用户

#### 3.2.6 更新指定用户

- **需求编号**: USER-006
- **需求描述**: 管理员更新指定用户信息
- **输入**: 用户 ID + 可更新字段
- **权限**: 仅超级用户

#### 3.2.7 删除指定用户

- **需求编号**: USER-007
- **需求描述**: 管理员删除指定用户
- **输入**: 用户 ID
- **权限**: 仅超级用户

### 3.5 Dify AI 代理模块

#### 3.5.1 发送聊天消息

- **需求编号**: DIFY-001
- **需求描述**: 代理向 Dify AI 平台发送聊天消息，返回 SSE 流式响应
- **输入**: 聊天消息内容、api_key_name（指定使用的 Dify 应用）

- **约束**: 需要用户认证

#### 3.5.2 文件上传

- **需求编号**: DIFY-002
- **需求描述**: 代理向 Dify AI 平台上传文件
- **输入**: Base64 编码的文件内容、api_key_name

- **输出**: Dify 返回的文件信息

#### 3.5.3 获取对话列表

- **需求编号**: DIFY-003
- **需求描述**: 获取用户在 Dify 平台的对话列表
- **输入**: user（用户标识）、api_key_name
- **输出**: 对话列表

#### 3.5.4 获取消息历史

- **需求编号**: DIFY-004
- **需求描述**: 获取指定对话的消息历史
- **输入**: user、conversation_id、api_key_name
- **输出**: 消息列表

#### 3.5.5 删除对话

- **需求编号**: DIFY-005
- **需求描述**: 删除指定的对话
- **输入**: 对话 ID、user、api_key_name
- **输出**: 删除结果

## 5. 数据需求

### 5.1 数据实体

系统涉及以下核心实体：

1. **用户（User）**：平台注册用户，包含认证信息和个人资料
2. **文件分析报告（FileAnalysisReport）**：用户上传文件的分析结果
3. **测评记录（TestRecord）**：用户完成心理测评的记录

### 5.2 数据流

**用户注册登录流：**
```
用户 → 注册/登录 → 后端验证 → 生成 JWT → 返回 Token → 后续请求携带 Token
```

**分析报告创建流：**
```
用户上传文件 → 前端处理 → 调用创建 API → 后端保存 → 返回报告 ID
```

**AI 咨询流：**
```
用户发送消息 → 后端代理到 Dify → Dify 返回 SSE 流 → 后端透传 SSE → 前端展示
```

**测评记录流：**
```
用户完成测评 → 前端提交题目/答案/得分 → 后端保存 → 返回记录详情
```

## 6. 接口需求

### 6.1 用户接口

- Web 浏览器访问前端应用
- 支持响应式布局，适配桌面和移动端
- 支持主流浏览器最新两个版本

### 6.2 外部接口（Dify AI）

**Dify 平台接口：**

| 接口 | 方法 | 说明 |
|------|------|------|
| /chat-messages | POST | 发送聊天消息，SSE 流式返回 |
| /files/upload | POST | 上传文件 |
| /conversations | GET | 获取对话列表 |
| /messages | GET | 获取消息历史 |
| /conversations/{id} | DELETE | 删除对话 |

**认证方式**: Bearer Token（Dify API Key）
**数据传输**: JSON
**流式接口**: text/event-stream
